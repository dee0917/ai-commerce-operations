# 範例網站

這三個站是同一條產線的實際產出。收在這裡是為了讓你**不用註冊、不用金鑰、一行指令**就能在自己電腦上打開一個完整的店，並且**並排比較三種完全不同的視覺方向**。這條產線的核心就是每個站都不該長得像同一個模板做的。

> **關於這些站的階段說明**
> 這條產線的合規檢查（含英國 DMCCA 的促銷標示規則）建立於 2026-07-31，
> 而清單中多數站建於 2026-03 到 06，**早於那道檢查**。
> 因此部分早期站的示範資料仍帶有促銷價欄位與樣板顧客評論，不符合現行標準。
> **這些是測試階段的產出，不是對外販售的商品頁**（沒有接金流、沒有開賣）。
> 現行檢查已納入產線，**2026-08-04 之後產出的站在建置時就會被擋下**，
> 要重跑驗證可以直接執行 `production-line/scripts/ecommerce-checklist.py <站的路徑>`。

> 另外，這三個站**早於現行的頁面規範與品質關卡，未跑過完整計分**，收錄它們是為了視覺方向的對照，不是當作合規範本。


原始碼與編譯後的版本都在，三個站也都有現成的線上版，想先看畫面可以直接點開：

| 站名 | 賣什麼 | 設計方向 | 線上版 |
|---|---|---|---|
| `auraguard` | 開運與能量飾品 | 溫潤的米色調、襯線字體、大幅實物攝影，走精品編輯風 | [sg-auraguard.vercel.app](https://sg-auraguard.vercel.app) |
| `gridwell` | 桌面與線材收納 | 結構化的格線排版、克制的用色，把「整齊」本身變成視覺語言 | [sg-gridwell.vercel.app](https://sg-gridwell.vercel.app) |
| `vanguard` | 隨身裝備與工具 | 深色戰術風、等寬字體、橘色警示色，強調機能感 | [sg-vanguard.vercel.app](https://sg-vanguard.vercel.app) |

> 線上版是較早的建置，repo 裡的 `dist/` 是最新版，兩者不是同一份。要看最新的請用下面的方式在本機跑。

三個站刻意走完全不同的視覺方向。**這是生產線的重點之一**：避免每個站看起來像同一個模板換色。

## 這三個站，跟線上那兩個示範站是什麼關係

首頁給的兩個可以直接點開的網址（[sg-thirdstop.vercel.app](https://sg-thirdstop.vercel.app)、[sg-tensile.vercel.app](https://sg-tensile.vercel.app)）**不是這三個站的線上版，是另外兩個站**。兩批的用途不一樣：

| | 線上示範站 | 本 repo 收錄的範例 |
|---|---|---|
| 是哪些站 | thirdstop、tensile | auraguard、gridwell、vanguard |
| 建立時間 | 2026-08-04，最新一輪產出 | gridwell 與 auraguard 是 2026-03，vanguard 沒有留下帶日期的建立紀錄 |
| 收錄什麼 | 只有部署好的網站，原始碼未收進本 repo | 原始碼、編譯版本、截圖都在 |
| 為什麼是這幾個 | 要讓人看到「現在這條線做出來長什麼樣」，所以用最新的 | 要讓人看三種差異最大的風格，所以從歷來產出裡挑 |

所以：**線上那兩個的原始碼不在這裡**（要看程式碼請看下面這三個）；**這三個則是原始碼與線上版都有**，網址在最上面那張表，也收在 [`live-sites.md`](live-sites.md) 的 35 站清單裡。

**兩批都不是全部。** 線上運作中的站共 35 個。33 個是 2026-08-03 以前的存量，另 2 個是 2026-08-04 最新一輪的產出。2026-08-05 逐一以 HTTP 實測，35 個全部回應 200。本機保有完整原始碼的有 23 個，這裡只收 3 個，是為了讓 repo 保持在可以下載、可以跑起來的大小。

## 怎麼看

### 只想看畫面

打開 `screenshots/` 資料夾，每個站有首頁、商品頁、手機版三張。

### 想在瀏覽器裡實際操作

編譯好的版本在每個站的 `dist/` 裡。**需要起一個本機伺服器**，一行指令：

```bash
cd examples/vanguard/dist
python -m http.server 8000
```

然後開 `http://localhost:8000`。

或者用 Node：

```bash
npx serve examples/vanguard/dist
```

> **還有一件事要先講**
> 用本機伺服器開站之後，從首頁點進去都正常；但如果直接在網址列輸入 `/shop` 或在內頁按重整，會看到 404。
> 這是單頁式網站的標準行為：路由由前端接管，需要伺服器端把所有路徑導回 `index.html`。正式部署到 Vercel 這類平台時，`vercel.json` 已經設好這個規則，不會有這個問題。本機用 `python -m http.server` 只是最簡單的靜態伺服器，沒有那個規則。

> **為什麼不能直接雙擊 `index.html`**
> 這些站用的是 ES 模組，瀏覽器基於安全規則不允許從 `file://` 載入模組，直接開會是白畫面。這是瀏覽器的限制，不是網站的問題。起一個本機伺服器就正常。

### 想跑開發模式改東西

```bash
cd examples/vanguard
npm install
npm run dev
```

## 前置條件

**Node 18 以上，或任何能起靜態伺服器的工具。**

**不需要任何 API 金鑰，不需要付費服務，不需要資料庫。** 這三個站是純前端，商品資料寫在程式碼裡。

```
<站名>/
├── src/              原始碼
├── dist/             編譯後可直接部署的版本
├── package.json
└── vite.config.ts
```

> ⚠️ **這三個站都早於現行的頁面規範**。目前的規範要求 11 類必備頁面、展開為 15 個路由，而這三個站的路由數是 auraguard 19、gridwell 5、vanguard 14。
> 它們收錄的理由是**視覺方向差異最大**，不是因為它們符合最新規範。
