# 後續規劃

## 六個規劃中的部門

目前運作中的七個部門，涵蓋的是「把商品賣出去」這條線：研究市場、做出店面、帶進流量、看懂數據。

規劃中的六個部門，涵蓋的是「賣出去之後怎麼處理」：

| 部門 | 要解決什麼 |
|---|---|
| 選品與採購 | 供應商評估、成本結構、跨境採購流程 |
| 商品與目錄管理 | 商品上架、圖文規格、庫存對應 |
| 客戶服務 | 售前諮詢、售後處理、退換貨流程 |
| 物流與履約 | 出貨、追蹤、跨境配送方案 |
| 金流與財務 | 收款、對帳、退款、匯率處理 |
| 法遵與風控 | 各國電商法規、廣告合規、平台政策 |

**這個順序是刻意的。** 在還沒開賣之前先建客服與物流，做出來的會是憑空想像的流程。先把「能不能賣」驗證完，再依實際訂單的樣態去建「賣出去之後」的職能。

其中法遵與風控已經有實際產出（跨境市場的法規與成本研究），只是尚未整理成常態運作的部門。

## 後端與金流

生產線目前產出完整的前端店面。後端已完成 WooCommerce headless API 的串接驗證，正式後端與金流待租用服務後接入。

**先做前端的原因**：一個店面能不能賣，決定於商品呈現、信任感、結帳流程的順暢度，這些全部在前端。後端是把已經驗證可行的流程接上實際的收款與出貨，屬於執行問題，不是驗證問題。

先把生成品質與驗收體系做穩，再接付費基礎設施，可以避免在還沒確認方向時就開始付月費。

## 生產規模

目前的生產線以訂閱制的運算資源運作，適合逐案生產與品質迭代。

若要提升到穩定的量產規模，運算資源需要改為按用量計費的方案。原因不是成本，是訂閱制有時間窗的節流設計，不適合連續高頻的生產工作。

**單站時間已實測：29 分鐘**（兩個站各自 30.1 與 28.2 分鐘）。
**單站的額度用量還沒有乾淨的量測值**，單站成本區間與由它推導的月產能都是推估，不是實測。
那兩個站是平行跑的，用量與當天其他工作混在同一個額度窗裡，拆不出單站數字。
要收窄它，唯一的辦法是讓一個站獨占一個額度窗跑完並全程記錄當次用量，量到之後把推估換成實際數字。
