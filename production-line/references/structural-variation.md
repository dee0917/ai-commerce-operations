# 結構隨機化 (Structural Variation)

> **目的**：DNA（Phase 1.05）決定風格與骨架，本模組在其上疊加一層，讓每站的**區塊組成/順序、分頁組合、組件變體**也每站不同，消除結構層的量產指紋。外觀不同 + 結構不同，才是真正看不出是同一套系統產出的。

## 1. 每站結構種子 (Structural Seed)

每次生成隨機一個 `structural_seed`（整數，如 `random.randint(1, 999999)`），寫入 `design-system/DECISIONS.md`。以下第 2-4 節的所有隨機選取都必須用這個種子驅動（如 `random.Random(structural_seed)`），確保**同一個種子永遠選出同一組結構**。可複現、可除錯，不是每次跑都語意上等價的骰子。

## 2. 首頁區塊組成 (Homepage Section Mix)

**錨點（不隨機）**：Hero 永遠第一個，Footer 永遠最後一個。

**區塊池（12 選 5-8，隨機順序）**：
USP信任條、特色商品、分類展示、品牌故事、熱賣榜、顧客評價、Lookbook穿搭情境、影片生活風格、促銷banner、社群牆(IG)、電子報訂閱、FAQ精選

**相鄰規則（輕度連貫，選完後校正，不是硬性模板）**：
- 電子報訂閱若被選中 → 挪到 Footer 前的最後 1-2 個位置（訂閱區塊適合收尾，不適合埋在前段）
- 品牌故事若被選中 → 挪到中間區塊的前半段（適合早一點建立信任，不適合壓在最後才出現）
- 特色商品／熱賣榜／分類展示三者屬「商品密集區塊」→ 不可連續出現 3 個，中間必須穿插至少 1 個非商品區塊（如評價、品牌故事、社群牆）

## 3. 分頁組合 (Page Set) — 品類感知 (Product-Category-Aware)

**核心必要頁（每站永遠都在，不受隨機影響，功能完整性優先）**：
首頁、商品列表、商品內頁、購物車、結帳 — 共 5 頁。

**選配頁：依商品品類配對，不是從通用池亂抽**

用 Phase 1.1 選定的商品分類，比對下方「品類 → 適合選配頁」對照表，找出該品類專屬的選配頁池；只從**該品類的池**中隨機選 1-4 個納入（不綁死頁數，選幾個由 seed 決定）。找不到對應品類時，才落回「通用 fallback」池。

### 品類 → 選配頁對照表

| 品類群 | 對應 `extracted_products.json` 分類（現有 20 類範例） | 適合的選配頁池 |
|---|---|---|
| 服飾/時尚 | （現有商品池未涵蓋，保留供未來品類擴充） | Lookbook、尺寸指南、穿搭指南、系列 Collection landing |
| 食品/飲品 | 咖啡與茶道類 | 食譜/沖泡指南、成分與產地、訂閱方案、禮盒組合 |
| 3C/電子 | 創作者攝影配件類、智慧穿戴與配件類 | 規格比較、相容性、保固/開箱、使用手冊 |
| 美妝/保養 | 香氛與療癒類 | 成分列表、使用教學、膚質測驗、Before/After |
| 家居/家具 | 收納整理類 | 保養指南、空間情境、材質說明、空間規劃 |
| 珠寶/配件 | 水晶掛飾類 | 保養方式、尺寸指南(戒圍/鍊長)、禮品包裝、材質證書 |
| 運動/戶外 | EDC 隨身裝備類、戶外露營小物類 | 裝備指南、使用情境、活動日曆、社群挑戰 |
| 靈性/身心療癒 | 傳統風水護身類、煙燻淨化類、水晶原石類、音療器具類、神聖符號類、案頭風水類、御守香囊類、藥草瓶飾類、能量卡片類 | 儀式/淨化教學、能量對應表、冥想引導、來源故事 |
| 生活風格/桌面文具 | 極簡桌面美學類、特殊文具類 | 使用情境、材質工藝、搭配建議、系列 Collection landing |
| **通用 fallback** | 對不到品類群時使用（如汽車內飾類等未分類商品，或未來新增的陌生分類） | 關於/品牌故事、Journal/Blog、FAQ、聯絡、Sale/Outlet、套組 Bundle |

> 對照規則以分類名稱關鍵字動態判斷（如含「水晶」「風水」「香」→ 靈性/身心療癒；含「電子」「智慧」「攝影」→ 3C/電子…），對不到才落回通用池。`extracted_products.json` 未來新增或替換分類時，不會因為查表查不到而選不出結果。

**結果**：每站頁數 = 5 個核心頁 + 1-4 個品類選配頁 = **6-9 頁**，依品類與 seed 浮動，不綁死固定頁數。同品類的兩個站也會因 seed 不同選出不同的選配頁組合；不同品類則選配頁池本身就不重疊，組合明顯不同。

## 4. 組件變體 (Component Variants)

每站在以下 5 組各挑一個（仍受 Phase 1.05 主 DNA 約束，不可違反 DNA 決定的骨架）：

| 組件 | 變體選項 |
|---|---|
| Header 導覽 | 橫向選單 / 漢堡常駐 / mega-menu |
| Hero | 全出血圖 / 左右分割 / 輪播 / 影片 / 文字主導 |
| 商品牆 | 整齊格 / 瀑布流 / 輪播 / 編輯混排 |
| 商品卡 | hover 顯資訊 / 常駐資訊 / overlay |
| 分類展示 | 大圖磚 / 橫向捲動 / 清單 |

選定結果記錄到 `design-system/DECISIONS.md`。

## 5. 防重複 (Anti-Repeat)

`data/structural-history.json` 是一個陣列，記錄最近 8 站的結構指紋：

> ⚠️ **這個檔案目前是空的**。規則寫進規範的時間比實際開始記錄的時間早，
> 舊站沒留下指紋且無法從成品反推。從下一個站開始才會有內容，
> 原因與為什麼不補舊資料見 [`../data/README.md`](../data/README.md)。

```json
[
  {
    "id": 1,
    "date": "2026-07-09",
    "brand": "...",
    "structural_seed": 123456,
    "section_order": ["Hero", "品牌故事", "特色商品", "...", "Footer"],
    "page_set": ["Home", "Shop", "Product", "Cart", "Checkout", "Recipe", "GiftBox"],
    "category_group": "食品/飲品",
    "component_variants": { "header_nav": "橫向選單", "hero": "全出血圖", "product_grid": "整齊格", "product_card": "hover顯資訊", "category_display": "大圖磚" }
  }
]
```

新站生成前，比對 `section_order` 或 `page_set` 是否與最近任一站完全相同：
- 若相同 → 用新的 `structural_seed` 重抽一次（不沿用舊結果）
- 記滿 8 站一輪後清空為 `[]`，開始新一輪（與 `data/design-history.json` 的輪替邏輯一致）

## 6. 執行時機

在 Phase 1.05（DNA 混血）、Phase 1.06（框架選取）之後、Phase 2（工程實作）之前執行。DNA 決定風格與基本骨架，本模組決定「放哪些區塊、什麼順序、哪些頁、哪種組件排法」，兩者疊加＝外觀與結構都每站不同。

> 本模組決定的是**內容/行銷頁面**組合（首頁區塊、選配頁）；會員中心（登入/註冊/訂單/個人資料）與搜尋頁屬於電商功能性基礎設施，不受本模組隨機影響，維持 [site-architecture.md](site-architecture.md) 既有規格不變。Phase 2 工程實作時，內容頁清單以本模組選出的「核心頁 + 選配頁」為準（非固定頁數），會員/搜尋頁在此之外照舊加上。
