# 電商網站生產線

輸入商品資料與定位，輸出一個可部署的完整電商前端。

**當前版本 v11.1**，版本演進見 [`VERSION_HISTORY.md`](VERSION_HISTORY.md)。

---

## 這條產線解決什麼問題

AI 生成的網站最容易被看穿的地方是**版型重複**。同一套模板換個顏色換張圖，做十個站就會看出來是同一個東西。

所以這條產線的核心不是「能生成網站」，是**讓每個站有各自的骨架**。設計規範庫裡收錄多種不同的版面結構、視覺語言與內容節奏，生成時依商品定位挑選並組合，而不是套同一個模板。

[`../examples/`](../examples/) 裡的三個站可以直接對照：同一條產線產出，走的是完全不同的視覺方向。

## 品質關卡

生成過程中內建多層檢查，不通過不往下走。檢查的是結構性問題：破圖、缺價格、斷連結、行動版破版、明顯的排版錯誤。

**產線自己的檢查只是第一關。** 交付前還要經過獨立驗收，由不同的角色拿清單逐項跑，看使用者真正會看到的畫面。驗收標準在 [`../quality/`](../quality/)。

## 執行環境與依賴

產線的**規範與流程是平台無關的純文字資產**，任何能讀檔的系統都能使用。

**執行層目前跑在 Claude Code 的 Agent Skills 上**，由它負責讀規格、生成程式碼、跑檢查、修正。

⚠️ **單獨拿這個資料夾無法跑起整條產線。** 部分步驟依賴本機環境中的其他元件（圖片生成、前端設計規範、商品資料來源），那些不在本 repo 範圍內。本資料夾的用途是說明產線怎麼設計、規範長什麼樣、產出品質如何把關。

**產出物則完全獨立**：生成出來的網站是標準的前端專案，不需要這條產線也能開發與部署。

## 名詞說明

| 名詞 | 意思 |
|---|---|
| 設計規範庫 | `references/` 裡的文件集，收錄不同的版面結構與視覺語言，用來避免每個站長得一樣 |
| 反面教材 | 明確記錄「這樣做會很醜」的實例，生成時主動避開 |
| 品質關卡 | 生成過程中的自動檢查點，未通過不進入下一階段 |
| 獨立驗收 | 由非產出者執行的交付前檢查，見 `../quality/` |
