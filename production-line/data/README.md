# 產線的記錄檔

這兩個檔案是產線用來**避免每個站長得一樣**的記憶。生成新站時會讀它們，
確認新站的結構與視覺不會跟前幾站撞在一起。

| 檔案 | 用途 | 現況 |
|---|---|---|
| `design-history.json` | 記錄每個站用的設計基因、底色系、主要字體。生成時強制迴避前三筆用過的底色與字體 | 有資料。⚠️ v11.0 之前的站沒有設計基因可記，那幾筆的 DNA 欄位是 `unknown`，且不列入比對 |
| `structural-history.json` | 記錄每個站的結構指紋（區塊順序、分頁組合）。生成時比對最近 8 站，完全相同就重抽 | **目前是空的** |

## structural-history.json 為什麼是空的

**這條規則寫進規範的時間比實際開始記錄的時間早。**

結構隨機化的規則寫在 `references/structural-variation.md`，
`SKILL.md` 也明訂生成後必須追加一筆。但舊站沒有留下結構指紋，而指紋無法從已完成的站反推出來。
具體從哪一版開始才真的寫入，目前查不到紀錄，這裡不推測。

**所以這個檔案從下一個站開始才會有內容。** 這裡把它留著並寫清楚原因，
比刪掉或補假資料誠實。

## 為什麼不補回舊資料

補回去要靠事後判讀已上線的站，那是猜測不是紀錄。
**一份混著真實紀錄與事後猜測的檔案，比一份空檔案更危險**，
因為後面沒有人分得出哪一筆能信。

`design-history.json` 的第 5 到 8 筆是 2026-08-04 回填的，
回填的是**看得到的事實**（底色、字體，直接從上線的站讀出來），
DNA 欄位維持 `unknown`，因為那是無法從成品反推的內部參數。
